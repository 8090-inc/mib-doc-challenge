Runtime contract:

```bash
docker run --rm --network none \
  --read-only --tmpfs /tmp:rw,nosuid,nodev,size=2g \
  --mount type=bind,src="/absolute/path/to/pdfs",dst=/input,readonly \
  --mount type=bind,src="/tmp/mib-output",dst=/output \
  mib-visible-submission /input /output/predictions.jsonl
```

The image accepts exactly the input directory and output path. It runs with a
read-only root filesystem and retains UID 0 solely so it can write the official
runner's host-created output bind mount. It uses no network, GPU, API key,
external service, or runtime model download.

### How the predictions were generated

`solution.py` partitions its input into bounded chunks and runs each chunk in a
fresh interpreter with no cross-chunk state, so every case is scored
independently of every other case. Chunk composition therefore cannot change any
row: the only in-process caches are two `functools.lru_cache` memoisations keyed
on an immutable `pdf_path`, which are per-file lookups.

These predictions were generated by running the submitted image repeatedly over
disjoint slices of the sorted validation set and concatenating the results:
`MIB-100001..101000`, `101001..102000`, `102001..103000` (as four 250-case
slices), `103001..104000`, and `104001..105000`. Rows are emitted by the
canonical writer, sorted by `case_id`, with duplicates rejected, and the merged
file was checked against `data/validation_manifest.csv` with
`scripts/validate_submission.py --require-complete`.

**Every container ran inside the official per-container contract** —
`--network none`, `--cpus 4`, memory at or below `8g`, `--pids-limit 512`,
`--read-only`, `--tmpfs /tmp`. No single container was given more resource than
the scoring runtime allows. Several ran concurrently on one host, which shortens
the wall-clock time to produce this file but changes no output.

Two environment overrides were used during generation and are worth naming:

- `MIB_PROCESS_RECYCLE_BATCH_SIZE=250` (image default 1000, and the code caps it
  at 1000) shortens the interval at which the worker interpreter is recycled and
  a durable chunk checkpoint is written.
- `MIB_CRASH_RECOVERY=0` disables the in-container single-worker retry so a
  native fault surfaces immediately instead of silently restarting a long chunk.

Both are operational knobs over process lifetime and failure handling. Neither
participates in extraction or adjudication, and neither can change a predicted
row. They were used because this host hit repeated native faults during
generation (`exit -5`, plus a `difflib` "unknown opcode" signature) consistent
with the long-run instability recorded in `MEMO.md`; shorter process lifetimes
and durable checkpoints contained the loss.

Scoring the image as 8090 does — one invocation over all 5,000 PDFs at
`--cpus 4` with image defaults — is unaffected and sits comfortably inside the
contract: measured throughput is 3.2 seconds per PDF against the 6-second
budget, roughly 16,000 seconds against the 30,000-second hard limit.
