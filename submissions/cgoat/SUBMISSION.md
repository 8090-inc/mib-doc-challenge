# Submission — cgoat

**Public solution repository:** <https://github.com/cgoat/mib-doc-challenge-solution>

It contains a `Dockerfile`, and the image accepts exactly two arguments:

```bash
docker build -t mib-submission .
docker run --rm --network none \
  --mount type=bind,src=/path/to/pdfs,dst=/input,readonly \
  --mount type=bind,src=/path/to/output,dst=/output \
  mib-submission /input /output/predictions.jsonl
```

## Approach in one paragraph

An offline document pipeline: PyMuPDF separates each page's trusted visible text
from untrusted hidden spans, OpenCV plus Tesseract read the scanned pages one
text line at a time, noisy readings are snapped to the closed field
vocabularies, page evidence is merged by the field manual's precedence order,
and a hand-written policy engine produces the adjudication. Confidence comes
from a 26-weight logistic model fitted on the public training labels. No LLM,
no VLM, no cloud OCR, no network. See `MEMO.md` for the details, the failure
modes, and what I would do with another week.

## Runtime contract

| Requirement | This submission |
| --- | --- |
| Network at runtime | None. No API keys, no external services. |
| LLM / VLM / cloud OCR | None. PyMuPDF, OpenCV and offline Tesseract only. |
| Image size | 0.23 GiB uncompressed (limit 4 GiB) |
| Model artifacts | `mib/calibration.json` (~1 KB) and `mib/lexicon.json` (~5 KB) |
| Runtime | 0.85 s/PDF measured on 4 vCPU / 8 GiB (budget 6 s/PDF) |
| Read-only root filesystem | Yes; all scratch under `/tmp` |

`predictions.jsonl` here was produced by that image running against
`data/validation/` under the exact limits in `DOCKER_SUBMISSION.md`
(`--network none --cpus 4 --memory 8g --pids-limit 512 --read-only`), and it
passes `scripts/validate_submission.py` against `data/validation_manifest.csv`
with 5,000 valid records and no missing case ids.

## Reproducibility

On the public training split the same image scores **115.62 / 150** with the
challenge's own `scripts/evaluate.py`: extraction 40.39/50, classification
59.79/80, calibration 15.44/20, 0 missing cases, and 9 catastrophic false
approvals against 431 true denials.

Both fitted artifacts are derived only from the public training labels and are
regenerated by scripts in `tools/`. Nothing is keyed to a case id or a filename
— case ids are read from the page footer inside each PDF. `python -m pytest
tests/ -q` runs 21 unit tests covering layout parsing, OCR normalisation,
prompt-injection resistance and every adjudication branch.
